# AI 就绪度：必须做 / 应该做 / 不必做

> 2026-08-15  
> 先定范围，再谈现状与排期。  
> 场景只有一个：**对外展示**。用户或 Agent 能方便拿到飞书经本项目整理后的数据，而不是飞书编辑/协同那套原始 JSON。

---

## 一句话

AI 就绪 = **发现入口 + 稳定只读出口**。  
不是再做一个飞书，也不是再做一个聊天机器人。

---

## 必须做（没有这些就不叫就绪）

让「人/Agent 能找到、能拿走、能引用」成立：

| 能力 | 用户得到什么 |
|---|---|
| **发现** | 打开 `/llms.txt`（或等价）知道本站有哪些文、机器入口在哪 |
| **列表** | `GET` 一篇目录：标题、摘要、分类/标签、**稳定公网 URL**、单篇接口地址 |
| **单篇正文** | `GET` 一篇干净正文：标题 + markdown 或纯文本 + 更新时间 |
| **公网地址正确** | 响应里是站点域名，不是 `localhost` |
| **一份调用说明** | 用户不读源码，复制几条 curl 就能导出 |

这五件对应「展示向结构化数据」的最小闭环。  
缺任何一件：要么找不到，要么拿不到，要么拿到的不能引用。

数据必须来自**现有中间模型**（`SiteData` / `post`），禁止再打一套飞书编辑 API。

---

## 应该做（强烈建议，但仍是同一出口上的增强）

让「方便拿走」更稳、更好集成，仍不改变产品形状：

| 能力 | 为什么算应该 |
|---|---|
| 字段契约写死（`version`、`url`、`updatedAt`、错误形） | 下游才敢接 |
| 列表可筛：类型 / 分类 / 标签 / 关键词 / 分页 | 站点不只是博客流 |
| 列表里的 json/md 链接点进去必通 | 发现和详情不能两套 slug |
| 无权限文明确字段，不 500 | 展示失败可预期 |
| 短验收脚本 | 以后改出口不会 silently 坏 |
| CORS 只读放开 | 浏览器小工具能调 |

这些都是「必须做」的加固，不是新方向。

---

## 不必做（本阶段不要做）

和「对外展示、拿走数据」无关，或成本远大于收益：

| 不做 | 原因 |
|---|---|
| 向量库 / RAG / 站内问答机器人 | 那是搜索产品，不是数据出口 |
| 写回飞书、评论写入 | 我们是只读展示 |
| 伪造 Notion recordMap 给 Agent | 和数据层原则冲突 |
| 付费墙 / 登录后私有语料 / Commerce | 不是当前站点形态 |
| 网页 protobuf、免鉴权爬飞书 | 不稳定，也不是结构化优势 |
| 为 Agent 重做 25 套主题 UI | 机器走 API，人走现有壳 |
| Webhook 实时同步、多租户开放平台 | 后置；ISR + 缓存够展示 |
| GraphQL、MCP 全家桶（除非出口先稳） | 先把 REST 三件事做清楚 |

---

## 和两条产品线的关系

- **必须 + 应该** = 方向 C（AI 就绪）的范围。  
- **部署只填 3 个参数** = 方向 D，并行但不塞进「AI 就绪」清单。  
- 主题换皮、封面图标边角 = 站点体验，也不是 AI 就绪。

---

## 下一步（范围定了之后）

先评现状，再排期。
